# 技術設計

## 一、施工邊界

- 只在既有隔離工作目錄 `.worktrees/website-home-redesign` 與分支 `feat/website-home-redesign` 施工。
- 保留上一版 `website/index-redesign.html` 作為比較，不直接覆蓋。
- 新版先使用另一個本機預覽入口，通過檢查前不取代正式首頁。
- 不合併、不推送、不部署、不修改正式網域或正式 Firebase 設定。
- 不修改 Google 登入、訪客／匿名驗證、會員登入或帳號轉換流程。
- 無法從專案與已確認需求取得答案時，集中寫入 `unconfirmed.md`，不得自行猜測。

## 二、官網架構

官網維持靜態 HTML、CSS、JavaScript，不更換技術架構。新增共用資源，避免每頁重複寫導覽、預約網址、樣式及動畫：

- `website/assets/site.css`：品牌色、版面、元件、響應式與減少動態效果。
- `website/assets/site.js`：手機選單、元素進場、互動動畫、手機固定預約列。
- `website/assets/site-config.js`：正式網址、自建預約、會員登入、LINE、電話、地圖與貓用品連結。

重要 SEO／GEO 文字直接存在 HTML，不得只在點擊或 JavaScript 執行後才出現。

公開頁面分成：

- 精簡首頁：品牌形象、關鍵資訊及六個需求入口。
- 七個完整主題頁：
  - 第一次射箭與教學方法
  - 價格、預約與到店須知
  - 裝備選購與弓種安全
  - 自製訓練／打怪系統
  - 正式會員、長期練習與比賽生活
  - 團康與包場
  - 教練專業與場館安全
- 保留並加強既有八個情境頁，不改網址。
- 隔離施工版直接移除 SimplyBook 舊頁、樣式、預覽與公開連結。

## 三、內容與專業證據

- 場館、學員、教學及比賽證據使用現有真實照片。
- 照片優先保留原始比例與人物、弓具、射箭動作，不為了卡片高度硬裁。
- AI 素材一律是明顯插畫風，首版約 4～6 張，不冒充真實紀錄。
- 專業資料以文字呈現：施聖凱、中華民國射箭協會 C 級教練、核准字號、效期、曾任松林國小射箭社團教練，以及學校與俱樂部帶隊參與比賽經驗。
- 比賽只寫「參與／帶隊參加」，不虛構代表資格、名次或獎項。
- GEO 內容先用短句直接回答，再補條件、證據與下一步。
- 畫面 FAQ 與 FAQ 結構化資料保持一致。
- 不使用「台南第一、唯一、最專業」等無法證明的比較宣稱。

## 四、SEO 與索引

- 可索引：首頁、七個完整主題頁、既有八個情境頁。
- 不可索引：預約 App、登入、會員、後台及所有預覽頁。
- 既有頁面保留 canonical 與網址。
- sitemap 納入所有正式可索引頁面，robots 與索引範圍一致。
- 只在畫面內容能證明時使用 LocalBusiness、Offer、FAQ、Breadcrumb 結構化資料。
- 重要文字保留為可讀 HTML，內部連結使用具體描述。
- 貓砂／餐包只在到店頁低調提及一次，不建立商品 Schema 或商品頁。

## 五、視覺與動畫

- 專業資訊使用穩定、俐落的層次動畫。
- 需求卡與教學流程可使用箭矢、靶紙命中與步驟推進。
- 自製系統區可使用較活潑的數值、裝備與打怪微動畫。
- 所有動畫靜音，首次進入畫面播放一次，不依賴動畫才能理解內容。
- 使用原生 CSS／JavaScript，不加入大型動畫套件。
- 滑鼠、觸控與鍵盤操作均有回饋。
- 支援 `prefers-reduced-motion`。
- 手機固定預約列支援安全區域，到 Footer 時縮小或收起，避免遮住聯絡資訊。

## 六、共用價格規則

建立一份預約前台與後台共用的價格資料：

- 一般：1／2／3 小時為 NT$350／650／650。
- 兒童／學生／敬老：NT$250／450／450。
- 自備器材：NT$250／450／450。
- 時數直接顯示 1、2、3 小時，移除「2送1」。

混合同行人數分為：

- 一般
- 兒童／學生／敬老
- 自備器材

每類可為零，合計必須為 1～8 人。總價為各類單價乘人數後加總。

「第一次來的人數」獨立輸入，範圍為 0 至同行總人數；回訪人數由系統推算。

團康價格只存在團康頁，不混入 1～7 人一般預約流程。

## 七、預約資料相容

新預約增加可分項的人數資料，例如：

```js
participantBreakdown: {
  general: 2,
  discount: 1,
  own_equipment: 1
},
participantCount: 4,
firstTimeCount: 1,
returningCount: 3
```

相容原則：

- 舊資料只有 `planType`、`participantCount`、`isNewStudent` 時，讀取時轉成單一類別，不批次搬移資料。
- 新資料仍保留舊讀取程式需要的欄位，避免其他畫面立刻壞掉。
- 容量計數器仍是唯一容量依據。
- 每個占用時段在同一個 Firestore transaction 更新 `count`、`newCount`、`returningCount`。
- 永遠維持 `count === newCount + returningCount`。
- 建立、取消、改期及後台修改都必須先讀完所有相關時段，再一次完成寫入。
- 一般／會員線上預約容量固定八人，第九靶位不開放在此流程。

## 八、三個預約入口

同一份人數、價格與相容規則供以下畫面共用：

- 公開訪客預約
- 正式會員線上約課
- 後台代建、修改、改期與結帳

公開預約只顯示「可預約／已額滿／不可預約／公休」。詳細新舊生與容量只在學籍系統及必要後台顯示。

登入與驗證完全不動，只修改預約表單狀態與預約資料。

## 九、後台結帳與優惠

- 結帳前可調整三類人數，合計仍不得超過八人。
- 同時保存原預約人數與最後結帳人數、各類小計及實收金額。
- 優惠資格到場確認，不在線上上傳證件。
- 射手編號 1～123 自動折抵 NT$50 必須保留。
- 每筆帳單只折一次 NT$50，綁定主要會員，不隨同行人數倍增。
- 歷史帳務不修改。
- 月卡維持獨立規則。

## 十、App Check 邊界

- 自建預約放上官網後不再是隱藏網址，需要防濫用。
- 本地版只準備 App Check 串接位置與友善錯誤提示。
- 本任務不啟用或修改正式 Firebase App Check。
- 正式上線前另行啟用並驗證，列為上線檢查項目。

## 十一、回復方式

- 原始 main 工作目錄保持不動。
- 上一版預覽繼續保留。
- 官網、預約與後台修改分成可獨立回退的提交。
- 若預約驗證未通過，仍可單獨檢視新版靜態官網，不合併應用程式修改。
