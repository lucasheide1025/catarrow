# 狩獵戰鬥演示與結算重建 PRD

## 目標

重建手機優先的自由狩獵單機／組隊戰鬥流程，使每次射擊只結算一次、貓咪每回合只行動一次，戰鬥資訊不遮擋怪物，並讓單機與組隊使用一致且可信的結算展示。

## 已確認事實

- 目前組隊戰鬥右上角常駐顯示玩家可造成的異常狀態與卡片加成，會遮住怪物。
- 目前輸入靶面分數「X（內十環）」時，分數相關效果會在整回合正式送出前提前結算；玩家可用退回／刪除輸入移除該顆 X，但先前效果仍會執行，再次輸入 X 便可重複施加異常狀態。
- 貓咪陪練回合的演示／效果疑似在同一回合發生兩次。
- 單機與組隊各自管理部分回合、勝利與獎勵狀態；共用 `BattleScreen` 也管理回合演示，存在重複所有權。
- 組隊房目前仍直接引用舊掉落表並維護自己的獎勵顯示狀態，造成結算畫面可能混用舊資料與實際領取資料。
- 既有產品方向為手機優先，輸入、等待、演出與回合摘要必須階段切換；等待休息時間不可略過，下一回合自動開始。

## 需求

### 1. 玩家加成資訊

- 移除遮住怪物的常駐效果清單。
- 改為不遮擋主要戰鬥區的單一「本場加成」按鈕。
- 點擊後以可關閉的抽屜／bottom sheet 顯示：卡片加成、專精加成、種族傷害、可施加異常、異常抗性、護盾／回復／蓄力等具有效期的效果。
- 單機與組隊使用同一資訊元件與中文顯示規則。

### 2. 一次性回合結算

- 每次玩家提交必須具有穩定且唯一的回合提交識別。
- X、10、9 等單箭輸入及退回／刪除都只更新本回合草稿，不得造成傷害、異常、回復、護盾、蓄力消耗或任何持久化副作用。
- 只有玩家按下「送出本回合」且整回合輸入通過驗證後，才能依完整箭組建立不可變的提交快照並一次結算。
- 同一提交的傷害、異常、回復、護盾、貓咪效果與怪物反擊最多套用一次。
- UI 關閉、重新開啟、重新渲染、動畫重播、重連與主持端重試不得重算效果。
- 演出狀態與權威結算狀態分離；演出可以恢復或略過，遊戲結果不可因此再次變更。

### 3. 戰鬥演示流程

- 建立一致的階段模型：輸入 → 已提交／組隊等待 → 玩家攻擊 → 卡片／異常效果 → 貓咪行動 → 怪物行動 → 回合摘要／休息 → 自動下一回合 → 勝負結算。
- 不適用的階段可以無演出通過，但不可由多個元件重複觸發。
- 貓咪每個有效回合最多行動一次；實際效果與畫面演示引用同一份回合事件快照。
- 保留組隊等待休息用途，不提供略過等待而直接進下一回合的常態流程。

### 4. 結算與掉落展示

- 單機與組隊共用同一套手機結算版型與獎勵項目元件。
- 版型允許模式差異，例如組隊貢獻／隊員資訊，但勝負、戰鬥摘要、獎勵與操作順序一致。
- 畫面只能顯示本場已由權威獎勵流程確認的結果，不得為展示再次抽獎，也不得回退讀取舊掉落表或舊戰鬥紀錄拼湊。
- 單機與組隊都在勝利結果確定時自動且僅一次入帳；結算畫面只讀取該次入帳產生的不可變收據，不提供會再次抽取或重算的領取按鈕。
- 每個獎勵項目顯示正確中文名稱、圖示、數量、階級與來源；零數量與未獲得項目不顯示。
- 實際入帳資料與 UI 顯示資料必須由同一份結算快照產生。
- 視覺採手機版「狩獵戰報」風格：上方為怪物戰果主視覺，中段顯示本場表現，下方顯示權威獎勵收據；組隊額外追加隊員貢獻列。
- 獎勵確認時可播放簡短亮光與入袋動畫，但不得以大量寶箱彈窗取代清楚的逐項收據。
- 自動入帳遇到離線或暫時錯誤時，戰果畫面仍可顯示，但獎勵區只能顯示「獎勵同步中，系統會自動重試」；不得先揭示前端推測的具體掉落。
- 待同步獎勵必須保存本場唯一 claim ID，並於網路恢復、重新登入或重新進入相關頁面時以同一 ID 自動重試；伺服器確認後再揭示且保存收據。

## 驗收條件

- 手機尺寸下怪物本體與主要狀態不會被玩家加成資訊遮住。
- 加成按鈕可開啟完整資訊並正常關閉，不改變戰鬥階段或重新觸發效果。
- 反覆輸入、刪除再輸入 X 不會提前造成任何效果；正式送出後，傷害與所有狀態效果只發生一次。
- 貓咪每回合只有一筆效果、一段對應演示與一筆摘要紀錄。
- 單機和 2–4 人組隊均遵循相同階段順序，組隊仍保留等待時間並自動開始下一回合。
- 單機與組隊結算視覺一致，且所列獎勵逐項等於實際入帳結果。
- 不再從 `LOOT_TABLE_GUEST` 等舊展示掉落來源生成本場結算內容。
- 勝利後即使重整、離場再回來或重開結算畫面，也只顯示同一份收據且不會再次入帳。
- 既有卡片、專精、抗性、防禦、護盾與貓咪引擎測試保持通過，並新增防重複與結算一致性的回歸測試。

## 非目標

- 不重做世界王、地下城或決鬥的完整戰鬥 UI。
- 不改變既有自由狩獵掉落機率與組隊人數加成數值；本任務先確保唯一資料來源與正確展示。
- 不重新設計卡片、專精或貓咪技能的數值平衡。
