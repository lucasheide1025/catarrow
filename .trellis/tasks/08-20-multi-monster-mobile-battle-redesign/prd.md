# 重新設計多人複數怪手機戰鬥 UI 與加成整合

## Goal

重新規劃「多人複數怪」戰鬥的手機 UI/UX，讓玩家在單一手機畫面內看懂必要戰況並完成每回合操作，原則上不需垂直捲動。同時盤點並補齊此模式與既有卡片、裝備貓咪、貓咪羈絆及其他戰鬥加成系統的整合。

## Requirements

- 以手機直向使用為主要情境，戰鬥中的核心操作必須在首屏可達。
- 完整體驗基準 viewport 為 `390×844`；`360×640` 仍須在不垂直捲動頁面的情況下完成核心操作，可縮減怪物圖、間距與次要文字，但不可犧牲可用的觸控熱區。
- 重整戰鬥資訊層級，保留決策必要資訊，其餘內容改為摘要、漸進揭露或可展開區域。
- active battle 採「戰場優先＋底部固定操作盤」：上方精簡戰況、中間怪物戰場、下方固定回合操作。
- 分數輸入保留 `X、10～1、M` 十二鍵，採兩排六鍵；每鍵維持可用觸控高度。已輸入分數以緊湊序列顯示，撤回刪除最後一箭、長按撤回清空；箭數填滿後凸顯送出按鈕。
- 隊友常駐資訊只保留存活狀態、目前 HP 與是否已送出；隊友 ATK／DEF、完整能力與加成來源移至主動展開的隊伍抽屜。
- 移除 active battle 中「橫向隊伍摘要＋完整隊伍卡」兩套重複呈現。
- 不犧牲三隻前排怪物、隊伍狀態、玩家輸入、攻擊模式與目標選擇等多人複數怪核心規則。
- 盤點單人、一般組隊與多人複數怪目前使用的戰鬥能力值與加成資料流。
- 確認怪物卡片、世界王卡片、裝備貓咪、貓咪等級／羈絆，以及裝備、專精、符文或其他既有加成是否有帶入多人複數怪。
- 本次採完整戰鬥效果一致，而非只校正面板三圍：一般怪物卡靜態三圍、族系攻防、套裝、天賦、異常，世界王卡條件被動，RPG 裝備／證照／圖鑑等基礎來源，以及裝備貓咪的等級、ATK、羈絆與既有攻擊／治療／護盾技能均納入。
- 戰鬥介面需提供精簡的「本場生效加成」入口，讓玩家能驗證實際套用內容。
- 戰鬥效果採三層呈現：常駐只顯示自己 HP 與最多 3 個重要狀態圖示；卡片／貓咪／異常觸發以短暫浮字回饋；「效果」底部抽屜提供本場生效加成、貓咪能力、狀態與完整回合戰報。
- 主畫面不常駐列出所有加成百分比。
- 單人與多人複數怪補齊戰鬥音效：開戰、選取／送出、箭矢飛行、命中／爆擊／落空、卡片／異常、貓咪行動、怪物反擊、擊倒、回合結束及勝敗均映射既有 `sound.js` SFX。
- Server 可以先確定勝負，但 UI 必須完整消費該回合 `RoundResolution.events` 後才顯示勝利／失敗。即使首擊秒殺，也要依序播放射箭、命中、傷害、擊倒與勝利演出。
- 演出不提供快轉、點擊略過或自動縮短；所有玩家按固定節奏完整觀看該回合事件。`prefers-reduced-motion` 只降低動態幅度，不省略事件或縮短到看不清。
- 複數目標效果規則：集火模式的傷害、穿甲、異常、卡片觸發與貓咪攻擊作用於選定怪物；全體模式維持每隻存活怪物 50% 傷害，攻擊型卡片效果與異常對各目標分別判定。
- 貓咪單體攻擊以玩家選定目標為優先，目標倒下時自動轉向第一隻存活怪；治療、護盾、防禦與回合末自我效果只作用於貓咪所屬玩家，不擴散全隊。
- 缺漏的加成應復用既有規則與來源，避免另建一套互相漂移的公式。
- 多人複數怪的進場能力快照與每回合結算採 server-authoritative：server 從正式玩家資料建立 loadout snapshot；client 只提交分數、攻擊模式與目標，不得自報三圍、卡片或貓咪加成。
- 卡片、異常與貓咪的隨機觸發使用 battleId／round 衍生的決定性 seed；同回合重試必須 idempotent，房主只能觸發結算，不能決定傷害數值。
- 玩家送出後顯示已鎖定與隊伍送出進度；server 尚未開始結算前可撤回 ready 並修改輸入。所有存活玩家送出後由 server 原子鎖定回合，此後不可撤回。
- 單人與多人複數怪進場時的基礎 HP／ATK／DEF，必須與角色頁「冒險者戰鬥屬性」顯示值完全一致。
- 條件式卡片、貓咪與戰鬥狀態效果須在基礎三圍之外另行套用及說明，不可造成無法解釋的面板差異。
- 規劃需涵蓋 UI 狀態、資料契約、相容性、測試與驗證方式；本階段先規劃，不直接實作。

## Acceptance Criteria

- [ ] 已記錄現行多人複數怪手機畫面的資訊與操作痛點。
- [ ] 已定義手機首屏必須常駐的資訊、可收合資訊及操作優先順序。
- [ ] active battle 不必展開隊伍抽屜即可完成選目標、選攻擊模式、輸入分數與送出回合。
- [ ] 在 `390×844` 與 `360×640` viewport 驗證 active battle 核心操作無頁面垂直捲動，主要按鈕具備足夠觸控尺寸。
- [ ] 已提出具體的手機版畫面配置與主要互動流程。
- [ ] 已列出所有既有戰鬥加成來源，並標明目前已接入、部分接入或缺漏。
- [ ] 一般卡、世界王卡與裝備貓咪的既有戰鬥效果在多人複數怪具有明確、可測試且可向玩家說明的作用結果。
- [ ] 每種主要 battle event 都有對應音效；音效失敗不阻斷回合。
- [ ] 秒殺 fixture 仍完整播放該回合所有事件，victory UI 只在 presentation cursor 抵達最後事件後出現。
- [ ] Presentation overlay 不提供 skip／fast-forward 控制，且使用者點擊不會直接揭示 terminal result。
- [ ] 已定義多人複數怪應採用的統一能力值快照／資料流與信任邊界。
- [ ] 偽造 client 能力值不會改變 server 建立的進場快照或回合傷害；同一回合重試不會重複攻擊或觸發效果。
- [ ] 同一份玩家資料下，角色頁、單人複數怪與多人複數怪的進場基礎 HP／ATK／DEF 完全一致，且測試逐項比對來源總和。
- [ ] 已制定 UI、戰鬥公式、組隊同步與回歸測試的驗收項目。
- [ ] `design.md` 與 `implement.md` 完成並經使用者確認後，才進入實作。

## Confirmed Findings

- 現行 active battle 依序垂直堆疊：戰鬥 HUD、橫向隊伍摘要、共享戰場、完整隊伍狀態、攻擊模式與 12 鍵分數輸入、戰報；手機必然需要大量向下捲動，且共享戰場與完整隊伍卡重複呈現部分資訊。
- 三隻前排怪物卡每張至少 `118px` 高，後排符文另起一列；僅戰場本身已占去大量直向高度。
- 回合操作位於怪物區與完整隊伍狀態之後，並非固定在拇指可達區；選目標、選模式、輸入分數、送出之間需要來回捲動。
- 多人複數怪目前只從一般怪物卡與射手等級帶入靜態 `HP/ATK/DEF`；一般卡片族系傷害／減傷、卡片天賦、套裝、異常、世界王卡被動未透過既有 `combatLoadoutSnapshot`／`cardTalents` 契約帶入。
- 裝備貓咪目前只同步 `catId`、名稱、類型與 `bondLv` 作為顯示資料；沒有同步 `catATK`、貓咪技能／修正值，也沒有在多人複數怪回合引擎觸發貓咪攻擊、治療、護盾等效果。因此「顯示有同行貓咪」不等於貓咪系統實際生效。
- `playerStats` 的基礎值可能已包含部分角色／裝備面板數值，但目前沒有保留 `statProvenance`，也無法在此模式清楚驗證各來源；需要改用統一、可追溯的戰鬥 loadout snapshot。
- 進一步追查確認數值不一致不是單純顯示問題：`MemberApp` 傳給單人與多人複數怪的是 Firestore profile 上的原始 `hp/maxHp/atk/def`；角色頁則先以 `calcArcherStats()` 彙總基礎、證照／紀錄、圖鑑與 RPG 裝備等來源，再加射手等級與卡片靜態三圍。複數怪頁只在原始 profile 值上補射手等級與卡片靜態三圍，因此確實漏掉 `calcArcherStats()` 內的多項外部面板加成。
- 修正後應以角色頁「冒險者戰鬥屬性」作為進場 HP／ATK／DEF 的基準口徑，並攜帶來源明細；條件式卡片、貓咪與回合狀態效果另列為戰鬥中修正，避免把面板值與動態效果混為一談。
