# PRD：地下城首次通關與世界王誕生系統重構

## 目標

修正地下城把普通通關誤判為全服首殺、個人首次通關沒有紀錄與必掉獎勵的問題；修正世界王 HP、狀態、結算與待領獎勵彼此不一致的問題，移除舊的前端自動生成機制，改成可累積全體活動進度、8 小時後開始計算且最晚 48 小時必定誕生新王的「世界王降臨進度」。

同時移除教練後台每天會看到的 Firestore 成本警訊橫幅，但保留底層成本權限控制與遠端政策，不解除任何資料庫保護。

## 已確認的現況

- 後台成本警訊由 `AdminCostControlBanner` 在教練後台與射手模式各渲染一次；底層 `CostControlProvider` 與 `assertCostCapability` 另有實際保護責任。
- 地下城全服首殺寫入 `dungeonFirstClear/{dungeonId}`。
- 地圖地下城的穩定分類是「六族 × T1～T6」；現有收藏品已經有對應各族各等級的首次通關紀念品資料。
- 現有流程使用 `mapDungeonId` 或執行個體 ID 呼叫首殺 API，導致每次新產生的地下城可能被視為全新首殺。
- 現有首殺獎勵只由房主端判定，且同一個 `firstClearBonus` 同時控制全服公告、貨幣加碼與收藏品，沒有區分：
  - 一般通關；
  - 玩家個人首次通關；
  - 全服真正首殺。
- 世界王目前有兩套狀態來源：完整 `worldBossEvents` 文件和精簡 `worldBossStatus/current`；舊資料可出現 `status=defeated` 但 `bossCurrentHP>0`。
- `WorldBossLobby` 每次開頁都呼叫 `autoSpawnWorldBoss()`；這是要移除的舊自動生成入口。
- 世界王待領獎勵目前只找「最新一筆歷史」或「畫面目前這一隻王」，容易漏掉沒有歷史快照、較舊但仍待領、或新王已建立後的玩家。
- 世界王請領由玩家自己寫入自己的獎勵，這個 self-claim 權限模型必須保留。

## 功能需求

### 1. 移除後台成本警訊

- 教練後台與教練射手模式不再顯示 `AdminCostControlBanner`。
- 不移除 `CostControlProvider`、遠端 `sysConfig/costControl`、成本能力檢查或真正的保護機制。
- 不再新增取代它的常駐警告。

### 2. 地下城一般通關、個人首次通關與全服首殺分離

- 一般通關：每次合法完成地下城都成立，只顯示一般通關結算與既有普通獎勵，不公告首殺。
- 個人首次通關：每位正式玩家第一次完成某個「族系＋T 等級」時成立，單人與組隊皆分別記錄每位實際參與者。
- 全服真正首殺：某個「族系＋T 等級」第一次被任何隊伍完成時成立；組隊只吃房主／隊長身分作為首殺擁有者，公告可列出全隊參與名稱，但不能讓每位隊員各自再搶一次。
- 同一個族系與 T 等級之後再次通關，只能是一般通關，不得再公告首殺。
- 寶藏系／隱藏地下城不加入六族首次通關圖鑑與全服首殺，除非已有明確對應收藏品。

### 3. 進場前首次通關偵測與提示

- 在地下城選擇／進場區顯示該玩家對目前「族系＋T 等級」的狀態：
  - 尚未通關：醒目顯示「首次通關獎勵尚未取得」及必掉收藏品預覽；
  - 已通關：顯示首次通關日期或已完成標記；
  - 無法判定的舊資料：顯示一般提示，不把它誤標為尚未通關。
- 組隊房主與隊員都看自己的個人首次通關狀態，不以房主狀態代替全隊。

### 4. 個人首次通關必掉特殊道具

- 每位玩家第一次完成對應族系與 T 等級時，必定取得該條目的首次通關限定收藏品一次。
- 重連、重複按領取、房主強制推進或多裝置同時操作都不得重複發放。
- 舊的全服首殺仍可有額外貨幣／公告，但「首次通關限定收藏品」改為個人制，不再只給真正首殺房主。
- 地下城圖鑑的收藏品 SVG／emoji 展示改為可辨識的小圖片；圖片不存在時保留有限 fallback，不造成無限重試。

### 5. 世界王舊自動生成機制下架

- 移除 `WorldBossLobby` 開頁呼叫 `autoSpawnWorldBoss()`。
- 不再依「擊倒後 24 小時」由任意玩家前端直接建立新王。
- 保留教練後台手動建立世界王。
- 舊 `autoSpawnWorldBoss` 不再有一般 UI 呼叫端，可保留為相容包裝或改為停用回傳，避免舊客戶端誤建新王。

### 6. 世界王狀態與 HP 一致性

- 活躍王必須滿足 `status=active` 且 `bossCurrentHP>0`。
- 被擊倒王必須滿足 `status=defeated` 且 `bossCurrentHP=0`。
- 玩家畫面、後台、精簡狀態文件與結算畫面都使用同一套正規化判定。
- 對現有 `status=defeated`、HP 仍為 6721/550000 這類矛盾資料，讀取時顯示為 0 HP，並提供一次性安全修復路徑把正式文件校正為 0；不得把它重新改回 active。
- 只有真正把 HP 從正數扣至 0 的交易可以寫入尾刀、擊倒時間與擊倒公告。
- 戰鬥送出後若這次確實擊倒世界王，必須顯示勝利／結算畫面；不能因舊畫面快照仍為 active 而顯示戰鬥失敗。

### 7. 全體參戰者待領獎勵

- 所有非訪客參戰者都能看到自己的待領入口，即使：
  - 他不是前三名或尾刀；
  - 歷史快照尚未建立；
  - 新的世界王後來已經建立；
  - 他重新登入或換裝置。
- 待領查詢以世界王事件文件與玩家參戰／claimed 狀態為準，不只看最新一筆歷史。
- 已領取者不再顯示按鈕；重複請領保持冪等。
- 「雪莉」類型的漏領案例要能被測試案例重現：排行榜最後一名、低傷害、非前三名、非尾刀，仍有參戰保底與可領入口。
- 世界王獎勵套用：
  - 全員基礎獎池均分（不因傷害為零而完全拿不到）；
  - 依傷害貢獻追加，但設有低等玩家保底；
  - 前三名額外獎勵；
  - 尾刀額外獎勵；
  - 參戰獎勵。

### 8. 世界王降臨進度

- 世界王被擊倒並完成結算後，先進入 8 小時休整期；休整期內不推進條件。
- 休整期結束後顯示「世界王降臨進度」。
- 同一個週期同時累積五項全體條件，任一條達標即可召喚；時間條件永遠作為最晚 48 小時的保底：
  1. 所有模式累積有效射箭箭數；
  2. 六族地下城任意等級合法通關次數；
  3. 七族怪物在任何合法模式的擊倒數；
  4. 休整期結束後的倒數時間；
  5. 貓貓村探索地圖實際消耗骰子數。
- 預設門檻先設為可由後台調整的平衡值：
  - 射箭 10,000 箭；
  - 六族地下城通關 30 次；
  - 七族怪物擊倒 500 隻；
  - 貓貓村骰子 300 次；
  - 48 小時自動召喚。
- 達標後以交易／冪等鎖只建立一隻王；多名玩家同時完成條件不得重複生成。
- 新王從可用世界王池隨機抽取，預設排除上一隻；教練後台仍可手動指定。
- 進度貢獻只接受現有合法結算點，不接受純前端按鈕自行增加。

### 9. 世界王獎勵重設

- 每隻王保有依類型／強度設定的基礎範圍，建立事件時將本次獎勵快照鎖死。
- 獎勵包含高額金幣、高額箭露與多個寶箱。
- 所有人都有全員基礎份；依傷害有額外貢獻份，並有最低保底。
- 前三名、尾刀、參戰與保底分開顯示，結算畫面清楚列出來源。
- 既有世界王卡、召喚卷、收藏獎盃與類別獎池能沿用，不因重構遺失。

## 驗收標準

- [ ] 教練後台與教練射手模式均不顯示成本警訊，成本能力保護測試仍通過。
- [ ] 同一族系同一 T 等級連續通關兩次，只有第一支合法全服交易會公告首殺。
- [ ] 組隊首殺只以房主作為首殺擁有者，全隊名稱可出現在公告；隊員不重複建立全服首殺。
- [ ] 每位隊員第一次通關時各自取得一次限定收藏品；第二次不再取得。
- [ ] 進場前能看到自己的首次通關狀態與獎勵預覽。
- [ ] 地下城圖鑑首次通關收藏品使用小圖片且手機可辨識。
- [ ] 世界王頁面不再自動呼叫舊 24 小時生成函式；教練後台手動生成仍可用。
- [ ] `defeated + HP>0` 的舊資料在所有畫面一致顯示 0 HP，修復後正式文件也為 0。
- [ ] 真正擊倒世界王的玩家完成攻擊後看到勝利與完整結算，而不是失敗。
- [ ] 最低傷害、最後一名、非前三與非尾刀的正式參戰者仍能查看並領取保底獎勵。
- [ ] 新王建立後，前一隻王尚未領取的玩家仍能找到待領入口。
- [ ] 世界王擊倒後 8 小時內不推進；之後任一社群條件達標或滿 48 小時，只生成一隻隨機新王。
- [ ] 箭數、地下城通關、七族擊殺、骰子消耗都只在既有合法結算成功後推進一次。
- [ ] lint、相關單元測試、Firestore 規則測試與 production build 全部通過。

## 不在本次範圍

- 不移除 Firestore 成本保護本身。
- 不自動替未參戰玩家發放世界王獎勵。
- 不重寫一般打怪、地下城戰鬥傷害公式。
- 不直接部署正式環境；完成本機驗證後另依使用者部署指示處理。
