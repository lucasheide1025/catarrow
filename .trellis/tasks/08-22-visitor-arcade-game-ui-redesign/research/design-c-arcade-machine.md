# 方案 C：貓弓魔法機台（Arcade Machine）

## 核心概念

把訪客版包裝成一台放在實體射箭場裡的「貓弓競技機台」：手機是計分面板與冒險窗，真正的射箭仍發生在靶道上。畫面有街機遊戲的高對比、短回合節奏與即時戰況，但世界觀不是太空或賽博龐克，而是由貓咪工匠打造的魔法射箭機台。

霓虹不是電子雷射，而是沿著木框、紙靶與符文流動的「魔法能量墨水」。主材質是深色胡桃木、磨損金屬包角、羊皮紙、布旗與彩色玻璃；視覺符號使用貓掌、尾巴、箭羽、月亮與童話森林。避免全息網格、太空艙、機械人、晶片紋路與科技術語，防止變成一般科幻遊戲。

設計原則：

- 一個畫面只突出一個下一步，首要操作永遠能在一秒內辨認。
- 遊戲資訊分三層：本回合必要資訊、戰局狀態、可展開的詳細資料。
- 射箭一回合形成固定節拍：看目標 → 實體射箭 → 輸入成績 → 快速結算 → 下一箭。
- 競技感來自比分、連擊、倒數與觀眾式回饋；童話感來自角色、材質、用語與場景敘事。
- 保留目前路由、資料、local-first 與既有功能，只重整資訊層級與呈現方式。

## 首次頁：機台吸引模式

首次進入像站到一台等待投幣的機台前，但 CTA 使用「開始射箭」，不使用「投幣」等與場館流程不符的詞。

### 畫面構成

1. 頂部是窄版機台燈箱，顯示品牌、今日場館與簡短標語「拉弓，讓貓咪帶你進入地下城」。
2. 中央是動態關卡窗：一隻貓站在木製靶道入口，後方三張地下城海報輪播掠過。動畫只做緩慢呼吸光、旗幟擺動與箭羽流光。
3. 下半部是一體化「玩家登錄面板」：暱稱欄位、橫向貓咪選擇帶、主要按鈕。不要拆成多張等權卡片。
4. 貓咪選擇以大頭像為中心，一次突出一隻；左右仍露出相鄰角色，點擊或滑動切換。每隻只有一句性格描述，不先揭露複雜數值。
5. 固定底部主按鈕顯示「選好貓咪，開始射箭」，完成暱稱和角色後立即可按。

暱稱預設聚焦但不強迫鍵盤長時間佔畫面；可提供隨機貓系暱稱。local-first 說明縮成按鈕下方一行「進度會保存在這支手機」，不搶主流程。整段首次設定應能在 10–20 秒內完成。

## 回訪大廳：射手控制台

回訪首頁改為機台的「選關控制台」，不是功能卡片總表。

### 第一視區

- 頂部狀態條：玩家暱稱、貓咪頭像、等級、體力／今日進度；保持一行並可點開詳情。
- 主海報位：若有未完成冒險，顯示大型「繼續第 N 關」海報，附剩餘敵人、目前路線與預估下一回合；若沒有，顯示推薦地下城。
- 海報下方只有一個發光主按鈕。「繼續冒險」或「開始第一場」，不並列其他主要 CTA。

### 第二視區

三個地下城以橫向海報軌道呈現，保留下一張約 20% 的露出提示可滑動。每張只顯示名稱、難度、短特色與進度章；點入後才看詳細規則。

### 次要功能

組隊、房間碼、對戰與商店收進底部「機台功能鍵」或可展開抽屜；統計、成就、背包放在玩家資料面板。它們仍可快速到達，但不與「開始／繼續」競爭。離線或同步狀態用小型訊號燈呈現，出錯時才展開說明。

## 地下城選擇：三張實體關卡海報

選關畫面像射箭場牆上的三張大型賽事海報。選中海報會往前推進，露出「本局任務、推薦方式、可能獎勵、繼續／開始」；未選海報維持可辨識的窄幅。

### 森林靶場

- 主色：苔綠、螢光青綠、蜂蜜金。
- 圖像：木靶、蘑菇燈、貓掌旗與圓潤怪物剪影。
- 語氣：新手友善、直接推進；難度以一至三枚箭羽表達。

### 月影岔路

- 主色：靛藍、月光青、洋紅魔法墨水。
- 圖像：紙燈籠、月牙靶、分岔的銀色箭線。
- 語氣：強調路線選擇與事件，不使用複雜 RPG 術語。

### 深淵挑戰

- 主色：炭黑、熔火橘紅、深紫。
- 圖像：裂紋石靶、撕裂布旗、警示爪痕。
- 語氣：高風險、高回報；用清楚的危險量表與確認步驟，避免只靠紅色區分。

海報必須保有紙張纖維、印刷套色偏移與貓咪插畫，使霓虹只成為能量輪廓，而非整張電子螢幕。

## 戰鬥 HUD：短回合競技轉播

戰鬥畫面採「中央舞台＋上下 HUD」，讓怪物和實體射箭任務成為視覺中心。

### 資訊配置

- 頂部左側：玩家與貓咪的小型狀態、可用技能；頂部右側：回合、總分、連擊。
- 怪物名稱正下方固定 HP 與狀態圖示，重要狀態可點擊查看白話說明。
- 中央：怪物、當前靶紙／目標環區、選中目標。受擊傷害直接跳在對應目標旁，避免中央文字遮擋戰場。
- 中下：一條「本箭任務帶」，例如「射 10 公尺靶・輸入本箭分數」。距離、靶紙、點擊分數模式沿用進場前鎖定設定，戰鬥中只顯示、不允許更改。
- 底部固定輸入台：大型分數鍵／靶面點擊區、清除、確認攻擊。依場外模式只顯示其中一種輸入，不同輸入方式不混在同一畫面。

### 回合節奏

1. `READY`（約 0.6 秒）：任務帶亮起，提示實體射箭。
2. `SHOOT`：畫面保持安靜，玩家完成實體射擊；不以強制倒數製造場館安全壓力。
3. `SCORE`：底部輸入台成為唯一高亮操作。
4. `RESOLVE`（約 0.8–1.5 秒）：箭線、傷害、貓咪協攻和狀態以短動畫依序發生。
5. `NEXT`：新目標帶滑入，立即開始下一箭。

全體攻擊同一拍在各怪物旁分別顯示傷害；集中攻擊則保持該目標高亮。狀態傷害只在正確怪物旁快速跳數字並保留名稱下圖示，不用長篇中央播報。勝敗以完整結算頁收尾，顯示本局分數、關鍵表現、獎勵同步狀態和明確的「繼續／返回地下城」。

## 手機互動

- 以 360–430 px 直向手機為主要基準；戰鬥不要求橫置，避免射箭後還要旋轉手機。
- 主要觸控區至少 48 px，高頻確認鍵建議 56–64 px；底部操作避開 safe area。
- 核心流程可單手完成：大拇指區集中在畫面下 40%，資訊觀看區留在上方。
- 海報用水平拖曳但同時提供明確的左右按鈕與頁碼，避免只靠手勢。
- 輸入後提供短震動、聲音與視覺三種回饋；聲音和震動可個別關閉。
- 鍵盤出現時，暱稱欄與主按鈕必須仍可見；戰鬥輸入盡量使用自有大鍵盤，減少系統鍵盤干擾。
- 支援 `prefers-reduced-motion`：取消鏡頭震動、掃光與大幅位移，保留色彩／圖示狀態變化。
- 所有霓虹文字仍需達到可讀對比；焦點環使用雙層亮框，不只靠顏色。

## 設計 tokens

### 色彩

| Token | 值 | 用途 |
| --- | --- | --- |
| `--cabinet-ink` | `#070A12` | 主背景，接近黑藍而非純黑 |
| `--cabinet-panel` | `#121827` | HUD 與機台面板 |
| `--cabinet-wood` | `#4B3024` | 木框與童話材質錨點 |
| `--parchment` | `#F4E7C5` | 紙靶、海報、長文字底色 |
| `--magic-mint` | `#58F5B5` | 主操作、成功、森林能量 |
| `--moon-cyan` | `#45D7FF` | 資訊、月影路線 |
| `--spell-magenta` | `#FF4FD8` | 稀有、連擊、魔法事件 |
| `--score-amber` | `#FFC857` | 分數、獎勵、目前焦點 |
| `--danger-coral` | `#FF615F` | 傷害、危險；搭配圖示與文字 |
| `--abyss-violet` | `#7A5CFF` | 深淵層級與首領能量 |

霓虹色只占畫面約 10–15%，大面積仍由深色機台與自然材質承接，避免視覺疲勞。

### 字體與數字

- 標題：窄體、略帶海報感的粗體字；中文字需選清晰的黑體替代，不追求過度裝飾。
- 內文與操作：圓角無襯線，呼應貓咪親和感。
- 分數、HP、房間碼：等寬數字並使用 tabular figures，跳分時不造成版面位移。
- 建議級距：12（輔助）、14（HUD）、16（操作）、20（區塊標題）、28–36（分數／關卡）、40–48（首次頁主標）。

### 形狀、間距與光效

- 圓角：小控制 8 px、面板 12 px、主海報 16 px；避免所有內容都變成柔軟大圓卡。
- 間距基準：4、8、12、16、24、32 px。
- 機台框可使用切角、金屬鉚釘與木邊；角色、紙張與對話保持柔和輪廓。
- 發光分三級：焦點 4 px、主 CTA 12 px、稀有事件 20 px；同一畫面最多一處持續脈動。
- 陰影使用冷色內陰影塑造機台深度，海報則用暖色實體投影維持紙張感。

### 動態

- `instant` 80 ms：按鍵壓下、分數輸入。
- `quick` 160 ms：狀態切換、傷害浮字。
- `beat` 280 ms：HUD 滑入、海報選中。
- `reward` 600 ms：升級、稀有獎勵；不可阻擋下一步過久。
- 曲線以快速進入、柔和停止為主；戰鬥演出總長優先控制在 1.5 秒內。

## 隱藏的複雜度

1. **繼續狀態不只一種。** 大廳需分辨單人、組隊、房間等待、戰鬥中與已結算未領取，主海報文案與 CTA 必須對應真實狀態，不能一律寫「繼續」。
2. **場外設定是戰鬥契約。** 距離、靶紙與輸入模式進場後鎖定；HUD 必須從權威資料讀取，重新整理後仍恢復相同模式，不能用前端暫存猜測。
3. **實體射箭沒有可靠的螢幕倒數。** 玩家拉弓與取箭時間不可預測，動畫不能自動推進或讓逾時看起來像失敗。
4. **組隊資訊密度。** 多位玩家、複數怪與狀態容易塞滿手機；預設只突出當前行動者與目標，其餘成員折疊成狀態列，重要事件再短暫展開。
5. **local-first 與跨裝置。** 離線資料、訪客識別、同步中、同步失敗和重複獎勵需要明確但不驚擾主流程的狀態；重整頁面不可錯接另一種戰鬥畫面。
6. **海報資產與內容長度。** 三地下城需各有辨識度，但仍要支援活動替換、鎖定、進度與多語長標題；應預留無插圖時的材質與圖示 fallback。
7. **效能與耗電。** 發光、粒子、模糊和長時間動畫在中低階手機上成本高；以 CSS 合成友善屬性、短生命週期粒子與靜態紋理為主。
8. **可及性。** 狀態不能只靠色彩與閃爍；海報、怪物狀態、分數鍵、選中貓咪都需要清楚名稱、焦點順序和螢幕閱讀器回饋。
9. **房間碼與錯誤恢復。** 加入失敗、房間不存在、斷線重連需留在使用者理解的情境內，提供重試／返回，而不是把人送到不相干的單人戰鬥。
10. **競技與安全。** 機台感不能鼓勵玩家邊持弓邊操作手機；文案要明確區分「放下弓後輸入成績」，且不使用催促實體動作的閃爍倒數。

## 取捨

- **競技刺激 vs. 射箭場從容：** 使用比分、連擊與短結算提升刺激，但不對實體射箭階段倒數；節奏壓力只存在於螢幕演出。
- **霓虹辨識 vs. 貓咪童話：** 霓虹提供街機輪廓與即時回饋，木材、紙靶、布旗、貓咪插畫與魔法用語負責品牌。若兩者衝突，優先保留童話材質。
- **資訊密度 vs. 即時掌握：** HUD 固定顯示 HP、目標、分數與主要操作；技能細節、完整紀錄、隊友數值改為點開查看。
- **海報沉浸 vs. 快速選關：** 大圖提升關卡吸引力，但同時保留難度、進度與清楚 CTA；不讓裝飾迫使玩家多滑一屏才能開始。
- **動畫獎勵 vs. 短回合：** 一般攻擊使用 160–280 ms 級動畫，只有勝利、升級與稀有獎勵可使用較長演出，並提供跳過。
- **單一主 CTA vs. 功能發現：** 大廳強推開始／繼續會降低商店與 PvP 曝光，因此次要功能需有穩定的底部入口，而非完全隱藏。
- **自有分數鍵盤 vs. 原生熟悉度：** 自有輸入能形成大按鍵和一致節奏，但需完整處理誤觸、清除、確認、鍵盤操作與無障礙，不能只做視覺皮膚。

## 一句話驗收畫面

第一次來的玩家看到的是「貓咪邀請我走進魔法射箭機台」；回訪玩家一眼看到「現在要繼續哪一關」；戰鬥中的玩家一眼知道「這箭射什麼、去哪裡輸入、打中了誰」。即使移除所有霓虹光效，木製靶場、紙海報、貓咪角色與童話地下城仍應讓產品保持獨有辨識。
