# 方案 A：沉浸式童話冒險／主機遊戲首頁

> 核心命題：玩家看到的不是「功能選單」，而是一個正在等待他踏入的世界。首頁以單一舞台、角色與目的地構成；任何時刻只突出一個下一步。

## 核心概念

設計語言結合「童話立體書」與「主機遊戲首頁」：畫面約 70% 是可呼吸的場景、20% 是電影感 HUD、10% 才是操作。貓射手與當前目的地是視覺主角，文字和按鈕浮在景深分明的場景之上，而不是被包進許多同級卡片。

三條原則：

1. **一幕一件事**：每個畫面只保留一個高對比主按鈕；組隊、競技場、商店、統計等功能依玩家情境出現，或收進「旅人背包」。
2. **角色先於數字**：先看到自己的貓、牠的狀態與目的地，再以徽章、短句呈現等級、裝備及加成；避免首頁鋪滿 RPG 數值。
3. **場景就是導覽**：森林入口、月光門與深淵裂隙是真實空間中的三個目的地，不是三張並排產品卡。玩家以橫向滑動或點選地標切換焦點。

整體構圖採「單一攝影棚」概念：背景層、環境特效層、角色層、互動層和 HUD 層始終維持一致景深。頁面切換像鏡頭移動到營地、地下城或戰鬥場，而非跳到另一個 dashboard。

## 首次頁

### 畫面

首屏是一座黃昏貓森空地。畫面上方只有小型 CatArrow 紋章；中央是一隻被暖光照亮的候選貓，左右邊緣露出前後候選角色的剪影。貓的名字、性格短句與一項容易理解的特色貼近角色呈現，例如「米米｜穩穩命中」。玩家左右滑動角色，背景光色與小型環境粒子跟著角色改變。

底部是半透明羊皮紙／霧面玻璃操作托盤：

- 暱稱輸入框，預設聚焦但不立即叫出鍵盤遮住角色。
- 選角進度，如「3 / 9」，搭配縮小的角色徽記列；不使用九張同級卡片。
- 唯一主按鈕「帶著米米出發」。未輸入暱稱時提供就地提示，不彈出模態視窗。
- 「進度只保存在這台裝置」放在安全區上方的安靜註記，不與主行動競爭。

### 互動節奏

第一次進入時，鏡頭由森林遠景推近角色，約 500ms；角色輕微回頭並拉弓，隨即停止循環大動作。輸入暱稱、滑選角色、出發可在 10–20 秒內完成。按下出發後，角色朝森林門前進，畫面藉同一扇門轉場到大廳。若開啟 reduced motion，改成 120ms 淡入淡出與靜態光暈。

## 回訪大廳

大廳不是選單，而是「冒險營地」：中央偏下站著玩家的貓，後方是一座通往當前進度的巨大傳送門；遠景可看見另外兩個尚未聚焦的目的地。角色旁只顯示暱稱、等級徽章與一句狀態，例如「月光迷宮等待你回來」。

### 主路徑

畫面底部永遠只有一個寬版主行動：

- 有未完成冒險：「繼續月光迷宮」
- 無進度：「踏入貓森遺跡」
- 有可恢復隊伍房：「回到隊伍」；房號與隊友狀態以小字附在按鈕上方

系統依 `mode`、可恢復房間與本機進度決定主行動，避免「繼續、組隊、輸入房號、競技場、商店」同時搶注意力。

### 次要入口

- 左下「地圖」開啟地下城選擇；右下「旅人背包」開啟底部抽屜。
- 背包抽屜內依序放角色／裝備、加入房間、競技場、商店、戰績；重置旅人資料只存在設定二級頁。
- 組隊不是常駐大卡。當玩家聚焦地下城時，在主要 CTA 旁以二段選項呈現「單人出發／邀請夥伴」；加入既有房間則在背包內輸入代碼。
- 新獎勵、商店可購買或隊友邀請，以場景中的微弱徽記提示，不新增首頁卡片。

頂部 HUD 僅保留貨幣與連線／本機儲存狀態，透明度低於主角和目的地。統計摘要不常駐；需要時由背包抽屜上拉查看。

## 地下城卡

「地下城卡」實際是可聚焦的電影海報式場景入口：手機一次只完整顯示一個目的地，左右各露出約 12–16px 下一幕邊緣，暗示可以滑動。切換時背景、環境音色、角色姿勢和 CTA 文案同步改變，底部以三枚圖章標示位置。

### 貓森遺跡

- 視覺：青綠樹冠、暖金陽光、苔蘚石門、小精靈光點。
- 資訊：`★ 入門`、一句「跟著足跡學會第一場狩獵」。
- 角色姿勢：放鬆、指向前路；風險語氣友善。

### 月光迷宮

- 視覺：靛藍月夜、銀色岔路、漂浮路標與遠方隊友燈火。
- 資訊：`★★ 路線選擇`、一句「每一箭都會改變下一條路」。
- 角色姿勢：觀察地圖；可在 CTA 上方出現「適合組隊討論」。

### 深淵巢穴

- 視覺：黑紫峽谷、熔紅裂隙、巨大怪物剪影；仍保留金色品牌光源，以免脫離同一世界。
- 資訊：`★★★ 高風險`、一句「深入，或帶著戰利品撤退」。
- 角色姿勢：壓低重心、拉弓戒備；不可只靠紅色傳達危險。

每個入口只顯示名稱、難度、單句玩法差異、進度和一個主要 CTA。掉落物、詳細規則、排行等由「查看旅程」底部抽屜承載。鎖定狀態以霧障和條件短句呈現，不把入口縮成禁用卡片。

## 戰鬥 HUD

戰鬥畫面以「怪物舞台＋射箭輸入托盤」分層，讓實體射箭仍是主體。

### 390 × 844 參考構圖

- **0–12%：任務列** — 返回／暫停、回合數、短目標，如「本輪命中 18 分」。不顯示大段規則。
- **12–55%：怪物舞台** — 怪物占最大面積，名稱與 HP 條貼近其上方；受擊數字、狀態圖示均錨定怪物，避免中央文字遮擋演出。
- **55–70%：玩家與貓** — 貓射手半身像、玩家 HP、當前增益。角色面向怪物，使視線自然導向戰場。
- **70–100%：射箭托盤** — 記分輸入、目前累計與唯一「發動攻擊」按鈕，完整落在單手拇指區及 safe area 之上。

輸入分數時托盤上推，怪物舞台只輕微縮放，不能被手機鍵盤完全擋住。按下攻擊後鎖定重複提交，托盤降至半高，依「射箭軌跡 → 命中 → HP／狀態 → 結果」播放一次明確回饋；權威結果未回來前不預演擊殺。多人戰鬥則將隊友行動呈現在舞台側邊的小型時間軸，主玩家操作仍保持唯一焦點。

勝負結算是舞台燈光改變後浮現的單一幕：勝利顯示戰利品與「繼續旅程」，失敗顯示「再次挑戰／返回營地」且只有一個視覺主按鈕。領獎重試、重新連線等技術狀態用短句保留在結果托盤，不讓演出掩蓋操作是否完成。

## 手機互動

- 主要 CTA 高度至少 52px，次要觸控目標至少 44 × 44px；常用操作集中在畫面下方 40%。
- 地下城與選角支援橫向拖曳、輕掃與點選徽記；一次滑動只移動一個焦點，並提供清楚的分頁文字供螢幕閱讀器使用。
- 長內容一律使用可停靠底部抽屜。抽屜有可見關閉鈕、焦點圈限與返回鍵行為；不可只靠向下滑關閉。
- 鍵盤開啟時保留輸入欄、錯誤提示與提交按鈕；使用 `100dvh`／safe-area 概念避免 CTA 被瀏覽器工具列遮住。
- 390px 寬度不產生頁面級水平捲動；場景輪播自身可橫滑，但焦點內容仍在安全邊界內。
- 動畫遵循「只動焦點物」：場景景深慢、攻擊回饋快、HUD 幾乎不動。reduced motion 移除推鏡、視差、粒子與震動，保留色彩、圖示和短淡入。
- 重要狀態不得只依靠色彩；HP、難度、鎖定、斷線均有文字或圖示。背景大圖上的文字需有固定暗色漸層，不依賴單張素材的明暗。

## 設計 tokens

### 色彩

| Token | 建議值 | 用途 |
|---|---:|---|
| `--world-ink` | `#101622` | 夜色背景、文字遮罩 |
| `--world-ink-soft` | `#233044` | 次級 HUD、底部抽屜 |
| `--parchment` | `#FFF4D6` | 主要文字、明亮托盤 |
| `--gold` | `#FFC857` | 主 CTA、焦點、品牌光源 |
| `--sky` | `#66D9FF` | 資訊、連線、魔法回饋 |
| `--forest` | `#45C98A` | 貓森遺跡主色 |
| `--moon` | `#8FA8FF` | 月光迷宮主色 |
| `--abyss` | `#C56CFF` | 深淵巢穴主色 |
| `--danger` | `#FF675F` | HP 危急、失敗；搭配圖示／文字 |
| `--glass` | `rgba(16, 22, 34, .72)` | 電影感 HUD；需驗證對比 |

### 字體與形狀

- 標題：圓潤但具有童話招牌感的 display 字體，`clamp(28px, 8vw, 44px)`；正文仍用高可讀無襯線字。
- HUD 數字使用 tabular numerals；最低正文 15–16px，輔助文字不低於 12px。
- 主 CTA 圓角 16px；抽屜 24px；HUD 膠囊 999px。避免所有容器都使用同一種大圓角，以免重回卡片拼貼感。
- 場景文字陰影 `0 2px 12px rgba(0,0,0,.55)`；浮層陰影 `0 18px 50px rgba(0,0,0,.35)`，不使用多層彩色陰影。

### 間距、景深與動態

- 基礎間距：4 / 8 / 12 / 16 / 24 / 32px；手機左右安全留白 16px。
- 層級：背景 `0`、環境 `10`、角色 `20`、互動 `30`、HUD `40`、抽屜 `60`、系統訊息 `80`。
- 微回饋 120–180ms；HUD／抽屜 220–280ms；場景轉換 420–600ms。攻擊演出可較長，但每一段都必須對應權威戰鬥事件。
- 動態曲線：UI 使用 `cubic-bezier(.2,.8,.2,1)`；場景推鏡使用較平緩 ease-in-out。避免所有元素同時彈跳。

## 隱藏的複雜度

1. **首頁其實有多種優先狀態**：一般回訪、未完成單人冒險、可恢復隊伍、可恢復決鬥、獎勵待領與離線狀態可能競爭主 CTA。需要先定義決策順序，否則「單一主行動」會在邊界情況失真。
2. **既有模式不可消失**：`loading / onboarding / hub / adventure / team / duel / shop` 仍需可達；本方案只重排入口層級，不更改路由、資料或 Cloud Functions 合約。
3. **Local First 的可信度**：本機儲存、匿名旅人、重整恢復與清除資料仍需有清楚狀態。電影感轉場不得讓玩家誤以為尚未存檔或重複提交。
4. **場景素材的焦點裁切**：同一張大圖在 390px、較矮手機與平板上的角色／入口位置不同。素材需預留文字安全區、可拆景深層，並提供低階裝置的靜態合成圖與載入骨架。
5. **內容長度與動態資料**：暱稱、地下城進度、房號、隊友數、貨幣與在地化文字可能溢出。HUD 需要截斷規則與展開入口，不能靠固定中文長度成立。
6. **恢復與冪等**：戰鬥送出、領獎、加入房間或重連期間，按鈕必須反映真實狀態並防止重複動作；視覺演出只消費已確認事件。
7. **無障礙的場景導覽**：視覺地標仍要有正確 DOM 順序、可見焦點、語意名稱、live region 與非動畫替代。拖曳輪播不能成為唯一導覽方式。
8. **現有單檔樣式膨脹**：`ArcadeApp.jsx` 已包含大量共用樣式與模式分流。實作時宜把舞台、HUD、底部抽屜及地下城入口視為可獨立驗證的視覺模組，但本設計不要求改變既有資料邏輯。

## 取捨

- **沉浸感換取較低的功能總覽性**：次要功能多一個抽屜操作，但主路徑更清楚，首次玩家不會被房號、商店、統計同時打斷。
- **場景品質換取素材成本**：三座地下城、營地與戰鬥需要一致的焦點裁切與明暗版本。可先以分層漸層、現有角色／怪物素材建立 MVP，再逐步補場景插畫。
- **電影感換取效能預算**：視差、粒子和模糊需受裝置能力與 reduced-motion 控制；首屏應優先載入當前場景，其餘目的地延後載入並可離線快取。
- **單一 CTA 換取狀態決策複雜度**：需要明確規則決定「繼續冒險」或「回到隊伍」誰優先，並讓使用者仍能從背包找到另一條路。
- **少量 HUD 換取資訊深度**：玩家無法在首頁一次看完所有數值，但能透過角色抽屜查看完整資料；這符合「角色與冒險先於 RPG 數字」的產品定位。

## 與一般卡片 dashboard 的明確差異

| 一般 dashboard | 本方案 |
|---|---|
| 多張同級卡片平均分配注意力 | 單一場景焦點與單一主 CTA |
| 功能名稱構成首頁 | 角色、目的地與當前故事構成首頁 |
| 三個地下城並排比較 | 一次進入一座電影海報式場景 |
| 統計、商店、房號常駐 | 依情境浮現或收進旅人背包 |
| 換頁像開啟另一個工具 | 鏡頭在同一世界中移動 |
| 裝飾圖服務卡片 | 場景本身就是資訊架構與導覽 |

因此，即使暫時沿用既有角色與怪物素材，畫面骨架也不應退化成「背景圖＋一排卡片」；核心驗收點是任何首屏截圖都能立刻辨識出主角、當前目的地與唯一下一步。
