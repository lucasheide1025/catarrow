# 技術設計

## 資訊架構

新增玩家頁面 ID：`specialization-runes`，中文標題「專精與符文」。

入口與導覽：

1. `MemberInventoryHub` 的「相關功能」第一張使用跨兩欄的大型圖片卡，導向新頁。
2. `MemberApp` 與 `AdminApp` 將新頁列入背包分區，底部背包導覽保持選中。
3. `MemberProfile` 原本「管理專精頁面」入口改導向新頁。
4. 訪客不顯示此入口；直接掛載時維持唯讀或安全返回，不開放正式資料寫入。

## 頁面結構

`EquipmentProgressionPage` 作為頁面外殼，使用兩個高辨識主分頁：

- 專精：武器／防具／飾品三組進度。
- 符文工坊：製作、合成、鑲嵌三個子區。

手機使用頁首固定分頁與單欄內容；平板／桌面允許雙欄，但操作按鈕、成本及說明不可縮成不可讀的小字。

## 元件邊界

- `EquipSpecializationPanel`
  - 保留既有讀取與交易函式。
  - 改為接受頁面模式並重新呈現槽位摘要、專精卡及操作狀態。
- `EquipmentRunePanel`
  - 保留製作與合成交易。
  - 改成卡片網格與清楚的資源列。
- 新增 `EquipmentSocketPanel`
  - 從 `RPGEquipPanel` 抽出開洞、鑲嵌、卸下 UI。
  - 使用既有 `openEquipSocket`／`setEquipSocketRune` 類交易函式與玩家即時 profile。
  - 先選部位卡，再管理三個洞，顯示裝備品級、洞數、成功率、王之印記成本與符文總加成。
- `RPGEquipPanel`
  - 移除符文圖片 helper、socket modal 與相關交易 imports/props。
  - 裝備視窗只保留資訊／升級及更換品項。

## 圖片策略

使用內建圖片生成製作一張無文字的橫向入口主視覺：

- 主題：奇幻射箭裝備工坊。
- 左側是發光弓具與三條專精能量軌跡；右側是四種符文與鑲嵌法陣。
- 延續目前 App 深藍、紫羅蘭、琥珀金的 2.5D 遊戲插畫風。
- 不在圖中生成文字，所有標題與說明由 HTML 呈現，確保清晰與無障礙。
- 圖片放入專案資產目錄並由 bundler 管理；保留原始比例，使用 `object-fit: cover` 時避免切掉核心主體。

頁面內專精、符文類別優先使用既有符文圖片與 CSS 卡片；不為簡單圖示大量生成重複點陣資產。

## 資料與相容

- 不修改 Firestore 文件格式。
- 不修改專精、符文成本、成功率或戰鬥公式。
- profile 更新仍由現有登入層訂閱傳播。
- 新頁只重新組合現有交易能力，不建立第二套資料。
- 避免同一頁重複訂閱相同玩家資料；專精資料與材料庫存保留現有一次性 reload 模式。

## 回滾

新頁與新路由可獨立移除；原元件交易函式不變。若新 socket UI 發生問題，可暫時恢復 `RPGEquipPanel` 原 socket 區塊，不需資料遷移。
