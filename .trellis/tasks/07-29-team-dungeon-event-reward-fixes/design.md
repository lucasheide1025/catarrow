# 技術設計

## 核心狀態機

非戰鬥房統一使用四階段：

1. `presenting`：共享內容已生成，玩家閱讀或選擇。
2. `resolved`：房主以交易式／冪等方式套用一次共享效果。
3. `acknowledging`：每位有效隊員寫入自己的完成或領取標記。
4. `completed`：房主確認全員完成後，清除房間暫存並返回地圖。

## 權限與資料來源

- 房主是事件與寶箱共享結果的唯一生成者。
- Firestore 協調房間是多人狀態的唯一真相來源，客戶端本地動畫不可重新擲骰。
- 個人確認與個人領取分開記錄，避免「看完」被誤認為「已發獎」。
- 推進判斷只接受目前仍存在且 `alive !== false` 的成員。

## 事件結算

- 新增純函式，把事件／選項解析為具體結果與共享更新內容。
- 隨機效果在房主結算時展開成確定效果並保存。
- 事件代價、隊員增益、怪物修正與金幣／物品發放使用同一份已解析結果。
- UI 徽章從已解析結果產生，不再只讀原始提示文字。

## 寶箱掉落

- 掉落產生器輸入至少包含 `family`、`difficultyTier`、`hidden` 與可重現種子。
- 素材池依族系與難度選擇；T1～T6 對應實際階級，不再固定封頂 T4。
- 金幣、素材數量及收藏品稀有度隨難度遞增。
- 三張牌都從同一個混合獎勵池加權抽取，類別與位置皆不固定。
- 抽選時避免三張完全相同；若初次結果缺乏差異，從其餘可用類別補入候選後再洗牌。
- 組隊房間保存共享寶箱內容與每位成員領取標記。

## 相容性與回復

- 單人模式仍可使用本地事件套用流程，但與共享模式共用純函式。
- 讀取舊房間缺少新欄位時，以未結算狀態處理，不破壞既有房間。
- 若共享寫入失敗，保持原畫面並顯示錯誤，不提前清除 `pendingRoom`。

## 第三層地圖

- `generateBranchFloor()` 直接產生已排序的五間王前房：三間隨機功能房、休息、商人；不再把休息與商人一起洗牌。
- 共用地圖將王房放在第 6 格、獎勵房放在第 7 格，連線、鏡頭與目前位置皆由同一序列長度推導。
- 單人與組隊都以 `branch.rooms + boss + treasure` 作為唯一推進序列。
