# 世界王改版規格：宣告制弱點

> 狀態：**規格定案中，未實裝**（2026-07-31 撰寫）
> 作者拍板方向：宣告制 + 弱點固定傷害 + 破防階段。「亂填是我家的事，好玩就好」→ **不做防作弊**。

---

## 1. 為什麼要改

作者回報三件事：**沒有打世界王的感覺**、**戰鬥過程無趣**、**低等玩家打不動，都是高等玩家在貢獻**。

這三件是**同一個根因**：世界王現在是一隻血很多的普通怪。

`src/lib/damage.js:221` 的註解寫得很白——

```js
// Single arrow damage for world boss (no part system).
export function calcWorldBossArrowDmg(score, myATK, bossDef, participantBonus = 1, dmgBonusPct = 0) {
  return Math.round(calcStandardArrowDmg(score, atkFinal, bossDef, 1) * (1 + dmgBonusPct));
  //                                                            ^ partMult 寫死 1
}
```

一般怪有部位系統（`monsterData.BODY_PARTS`，11 個部位、倍率 1.0~1.5），**世界王刻意關掉了**。所以世界王的傷害只剩 `分數 × 攻擊力`，兩者都隨等級單調成長：

| | ATK | 平均分 | 每箭傷害 |
|---|---|---|---|
| 新手白板 | ~30 | 5 | **~18** |
| 114 級好裝 | ~300 | 9 | **~183** |

**十倍差距**，而且整場戰鬥玩家**沒有任何一刻需要做決定**——按 30 次分數就結束了。不無趣才怪。

## 2. 現況事實（改之前必須知道）

| 事實 | 位置 |
|---|---|
| 一次出擊 = **5 回合 × 6 箭 = 30 箭** | `WorldBossAttack.jsx:227` |
| 王血量 **10 萬 ~ 110 萬** | `worldBossData.js:29-` |
| 參戰加成：每位隊友 +15% ATK | `getParticipantBonus` |
| R2 強攻 / R4 終結（王打玩家）已有完整破解系統 | `worldBossStrikeEngine.js` |
| 落點座標 `nx, ny` **已經有存** | `targetFace.js:162` |
| 但輸入有兩種模式：⌨️點分數（無座標）／🎯點靶面（有座標） | `TargetFaceOverlay.jsx:18` |
| 一般怪的部位是**分數隨機決定**，玩家不選 | `monsterData.resolveHitPart` |

**兩個關鍵限制**：

1. **不能靠座標當主軸**——會把按分數鍵的玩家整個排除。
2. **不能沿用一般怪的部位系統**——那是「射完才知道打到哪」，沒有決策，換皮而已。

## 3. 核心機制：宣告制（call your shot）

**射之前先選部位，每個部位有一條分數門檻。射完看你有沒有兌現。**

| 部位 | 門檻 | 命中效果 | 沒達標 |
|---|---|---|---|
| 👁️ 眼 | **≥9** | 固定重傷 ＋ 破防 3 點 | 擦過：一般傷害 ×0.5，破防 0 |
| 🫀 心 | **≥7** | 固定中傷 ＋ 破防 2 點 | 擦過：一般傷害 ×0.5 |
| 🦵 腿 | **≥5** | 固定低傷 ＋ 破防 1 點 ＋ **中斷牠的蓄力** | 一般傷害，破防 0 |
| 🐉 尾 | **≥3** | 固定微傷 ＋ 破防 1 點 ＋ **降低下次強攻倍率** | 一般傷害 |

**判定是決定性的**：分數 ≥ 門檻 = 命中，不再擲骰。玩家賭的是自己的穩定度，這正是射箭真正的技術。

**為什麼這能救觀賞性**：每一箭之前都有一個真實的決定——我今天狀況好，賭眼睛？還是穩穩打腿把牠的蓄力打斷？撞球指定球入袋是同一個道理。

### 階段輪替

王有三階段（血量 100→66%→33%→0），**每階段換一組可打的部位**：

- 第一階段：全部可打
- 第二階段：牠護住眼睛（👁️ 宣告無效，強制改用心/腿）
- 第三階段：狂暴，護住心臟，但**破防槽累積速度 ×1.5**

強迫所有人改變宣告，戰鬥中段不會變成重複勞動。

## 4. 傷害模型：這才是平衡的關鍵

> ⚠️ **弱點傷害不乘玩家攻擊力，而是王最大血量的固定比例。**

這是整份規格最重要的一句。只要傷害是 ATK 的函數，不管包裝成什麼樣，114 級的一箭就是抵新手五十箭——換皮而已。

```
每箭傷害 = 一般傷害（照舊，ATK 公式）＋ 弱點固定傷害（bossMaxHp × pct）
```

| 部位 | 固定傷害 pct | 20 萬血的王 = |
|---|---|---|
| 👁️ 眼 | 0.10% | 200 |
| 🫀 心 | 0.06% | 120 |
| 🦵 腿 | 0.05% | 100 |
| 🐉 尾 | 0.03% | 60 |

**驗算**（20 萬血的王）：

| | 原本每箭 | 改後每箭 | 差距 |
|---|---|---|---|
| 新手（平均 5 分，宣告腿，命中率 ~60%） | 18 | **~78** | — |
| 114 級（平均 9 分，宣告眼，命中率 ~55%） | 183 | **~293** | — |
| **貢獻比** | **10.2×** | **3.8×** | ✅ 壓縮 |

老手仍然比較強——那是他該有的優勢，裝備和等級沒有白練。但新手從「打不動」變成「打得動」。

### 破防槽：讓新手的貢獻是**平等的**

傷害榜壓不到完全平等，也不該壓。但**破防槽算「命中次數」，不算傷害**：

- 新手打中腿 ×4 = 4 點
- 老手打中眼 ×4 = 12 點（眼 3 點/次）

眼睛值比較多，但門檻也高得多——**新手穩穩打腿，累積速度不會輸太多**。

破防槽滿 → **全場「破防！」全員增傷 ×1.5，持續 2 回合**。這一步把各自輸出變成團隊節奏，也是世界王最該有的「一起打一隻」的感覺。

排行榜同時顯示 **傷害榜** 與 **破防貢獻榜**——後者是新手真的排得上去的那個。

## 5. 靶面模式加碼（選配，不強迫）

點靶面的人有 `nx, ny`，多一層玩法：

**王的弱點顯示在幾點鐘方向**（例如「2 點鐘」），要分數達標 **且** 落點在該象限 → 固定傷害 ×1.5、破防 +1。

做成**加碼而不是必要條件**：不逼任何人換輸入方式，但給願意練落點控制的人一個舞台。按分數鍵的玩家完全不受影響。

## 6. 全新流程：預告 → 抉擇 → 分歧

> 作者 2026-07-31 拍板：**戰鬥過程、畫面、流程全部可以重新設計**；只有「玩家六維／裝備／卡片／貓貓」沿用既有架構帶入。

現在的流程是 5 回合 × 6 箭、王在 R2/R4 反擊——**沒有節奏，只有次數**。新流程把一場出擊做成三個節拍的循環：

```
┌─ 蓄力回合 ─────────────────────────────────┐
│ 王開始充能，上方出現意圖條「3 箭後發動」      │
│ 此時牠的弱點外露 → 固定傷害 +50%             │
│ 抉擇：貪輸出？還是分箭去打腿把它打斷？        │
└───────────────────┬───────────────────────┘
                    │
        ┌───────────┴───────────┐
   打斷成功                  沒斷成
   （腿部累積夠）            （箭不夠／沒達標）
        │                       │
┌───────▼────────┐    ┌─────────▼─────────┐
│ 王硬直踉蹌       │    │ 大招發動           │
│ 下回合全部位開放 │    │ 全隊掉血＋減益      │
│ 固定傷害 ×2      │    │ 破防槽被打掉 20%    │
│ 「破綻！」大字   │    │ 王咆哮、畫面震      │
└─────────────────┘    └───────────────────┘
```

**這才是「打世界王的感覺」**：每回合開始你都知道牠要幹嘛，然後必須決定要貪還是要防——而且是**全場一起決定**，因為打斷需要的腿部命中是所有人共同累積的。

一場出擊仍是 5 回合 × 6 箭（既有節奏玩家熟悉，不動），但每回合都是上面這個分歧。

比照 `src/guild/` 的成功先例（domain 純函數 + ui + data 三層）。**舊的 `src/components/worldboss/` 完全不動**，新舊並存到穩定為止（既有慣例，見 `battle-ui-redesign.md` 實裝計畫第 3 條）。

### 鐵律：domain 產生 log，UI 照 log 順序重播

公會改版時最大的一個 bug 就是**演出按事件類型分桶**，導致「怪物全滅前系統已結算，直接跳過戰鬥動畫」。修法是 `guildBattlePresentation.buildBattleTimeline`——**保留 log 原順序**。

這裡從第一天就這樣做：

```js
// domain：只算，不演
resolveRaidRound({ state, arrows, calls }) → { state, log }

// ui：照順序重播，每種事件有自己的停留時間
buildRaidTimeline(log) → [{ ...event, atMs }]
```

**好處**：所有聲光效果都掛在 log 事件上，不是散在 setState 裡——想加特效就是加一種事件，不會再出現「畫面跟結果對不上」。

### 沿用既有架構的部分（不重寫）

`raidLoadout.js` 是唯一的接縫：

| 帶入 | 來源 |
|---|---|
| 六維／等級加成 | `calcArcherStats`（`monsterData.js`） |
| 裝備加成 | 既有裝備系統 |
| 卡片加成 | `calcEquippedBonus`（`monsterCards.js`）、世界王卡 3 張 |
| 貓貓夥伴 | 既有貓咪協戰 |
| 靶紙格式／輸入模式 | `targetFace.js`、`TargetFaceOverlay.jsx` |

## 8. 版式：討伐版式（世界王專用）

`battle-ui-redesign.md` 的定案版式把**怪物放右上小卡**——那對地下城是對的，但世界王的玩法是**看著牠的身體選部位**，縮在角落就沒得玩。

**共用設計語言與元件（設計 token、玩家卡、計分覆蓋層、貓貓演出），版式獨立。**

```

│ ▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░  全場共享血條 63%    │
├────────────────────────────────────────────┤
│                                            │
│          ╱                    ╲            │
│         │      王  立  繪      │  ← 佔上半 │
│         │   👁️     🫀          │    可點    │
│          ╲   🦵        🐉     ╱   部位熱點 │
│                                            │
│   ⚡ 深淵之息  ▓▓▓▓▓▓░░░░  3 箭後發動      │
├────────────────────────────────────────────┤
│  破防 ◍◍◍◍◍◍◍◍◍◍◍◍░░░░░░░  18 / 30       │
├────────────────────────────────────────────┤
```

| 區域 | 內容 | 為什麼在這 |
|---|---|---|
| 頂部 | **全場共享血條** ＋ 階段 ＋ 參戰人數 | 世界王的血是大家一起打的，這條是「共鬥感」的來源 |
| 上半（55%） | 王立繪 ＋ **4 個部位熱點** | 玩法核心是看著牠選部位，必須夠大 |
| 意圖條 | 技能名 ＋ 進度 ＋ 剩幾箭 | 讓抉擇有依據，不是猜 |
| 破防槽 | 全場共享 | 團隊節奏的視覺化 |
| 宣告列 | 4 顆大按鈕，**選了才能計分** | 決策在射之前，不是之後 |
| 左下 | 玩家卡（沿用既有） | 跟其他模式一致 |

**被封鎖的部位**：打上鎖鏈圖示、灰掉、不可選——階段轉換時玩家一眼看到「規則變了」。

## 9. 聲光效果（作者要求：一定要漂亮、要夠多）

### 9.1 分層背景（景深）

三層視差：遠景天空（緩慢飄移）→ 中景場地 → 前景碎石（隨鏡頭震動位移）。

### 9.2 特效表

| 事件 | 畫面 | 音效 |
|---|---|---|
| 宣告部位 | 該熱點紅色鎖定框由大收束 ＋ 準星四角收合 ＋ 其餘部位降到 40% 亮度 | `sfxLockOn` |
| 蓄力中 | 王身上流動的能量線條、意圖條脈動、畫面邊緣暗角漸強 | `sfxCharge`（低頻漸強） |

| 一般命中 | 小幅震動 ＋ 白色傷害數字 | `sfxArrowHit`（既有） |
| **擦過（宣告失敗）** | 箭彈開、火花、王身體晃一下（嘲諷） ＋ 灰色「擦過」 | `sfxDeflect`（金屬） |
| 破防槽累積 | 槽格逐一點亮，最後 5 格開始脈動並泛白 | `sfxGaugeTick`（音高隨進度上升） |
| **破防！** | 全螢幕白閃 → 0.4s 慢動作 → 王跪地 → 「破防」大字撞入 ＋ 金色衝擊波 ＋ 全員頭上冒 ×1.5 | `sfxBreakthrough`（全場最重的一個） |
| **打斷成功** | 蓄力條**碎裂**成粒子、動作硬生生停住、踉蹌後退 ＋「破綻！」 | `sfxInterrupt` |
| 大招發動 | 螢幕紅色暗角 ＋ 強震 ＋ 招式名以血字掃過 | `sfxBossUlt` |
| 階段轉換 | 王咆哮、鏡頭拉遠再推近、**整體色調轉換**（II 轉紫、III 轉紅）、封鎖部位鎖鏈落下 | `sfxPhaseShift` |
| 連續命中 | 右上角 combo 數字堆疊放大（3 連以上發光） | `sfxCombo`（音高遞增） |
| 最後一擊 | **擊殺者專屬**：慢動作、王倒下、金色光柱、擊殺者名字全螢幕 | `sfxWorldBossFall` |

音效全部用 `lib/sound.js` 的 Web Audio 合成（`noiseBurst`／`distTone`），**不加音檔**——專案既有慣例。

### 9.3 效能紀律（手機上不能卡）

- 動畫一律 CSS `transform`／`opacity` keyframes，**不做 JS 逐幀**。
- 粒子單次上限 16 顆，播完即移除節點。
- 鏡頭震動掛在容器用 `translate3d`，不動個別元素。
- 尊重 `prefers-reduced-motion`：關掉震動與閃光，保留資訊性動畫。

## 12. 落地順序

1. **domain 純函數 + 測試**（`weakPoints`／`breakGauge`／`raidPhases`／`bossIntent`）——零風險，先把規則跑對。
2. **平衡模擬測試**——比照 `src/guild/domain/guildBalanceSimulation.test.js`：模擬新手／中手／老手各 30 箭，斷言貢獻比落在 **2.5×~4.5×**。數字微調全靠這支，不靠手感。
3. **`raidFlow` 狀態機 + `raidTimeline`**——log 順序從第一天就守住。
4. **美術生成**（背景與特效素材）。
5. **後台測試畫面**（`AdminWorldBoss` 開沙盒分頁）：假資料驅動，把版式與**所有特效**先做完看爽度。← 既有慣例「先驗證再實裝」。
6. **`RaidScreen` 正式接線**，`?wb2` 切換新舊。
7. Firestore 欄位、破防貢獻榜。
8. 穩定後才拆舊的 `WorldBossAttack.jsx`（2023 行）。

## 13. 明確不做

- ❌ **防作弊**——作者明示「亂填是我家的事，好玩就好」。
- ❌ **強制靶面輸入**——象限只是加碼。
- ❌ **AI 生成教練／師母／YUMI／九隻貓的立繪**——他們是真人與真貓。
- ❌ **改一般怪的部位系統**（`monsterData.BODY_PARTS`）——那是另一套設計，能跑就別碰。
- ❌ **動 `src/guild/`**——兩套系統互不相干。
- ❌ **重寫玩家數值／裝備／卡片／貓貓**——只透過 `raidLoadout.js` 轉接。
- ❌ **逐箭即時同步破防槽**——成本會爆。
